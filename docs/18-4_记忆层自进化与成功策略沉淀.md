# 18-4 记忆层自进化与成功策略沉淀

**本章课程目标：**  
- 理解 Store 从"存偏好"到"存成功策略"的能力升级——让 Agent 的每一次成功经验都能被未来的自己复用。  
- 掌握成功策略的定义、提炼、存储、检索、注入全链路。  
- 理解 Skill Library（技能库）的概念和 SkillRL 思路——把轨迹蒸馏为可复用的自然语言技能。  
- 掌握 fork 策略的动态调整——基于平台历史成功率自动调整 fork 候选平台优先级。  
- 看清记忆层自进化和 Prompt 自进化的区别：Prompt 是"全体用户共享的规则"，记忆层是"个性化 + 场景化的经验"。  

**学习建议：** 这是自进化系列的"收官章"，也是 3x3 矩阵里"External Files"层的深度落地。第 6 章给了 Store 的基础 CRUD，本章让 Store "自己变聪明"——从被动存储升级为主动积累和推荐经验。

## 1、Store 的能力升级  

### 1.1 当前 Store 只做了什么（第 6 章）  
```text  
第 6 章的 Store：  
  - 存什么：用户偏好（"不要塑料" / "偏好小众" / "预算 300"）  
  - 写入时机：每次 ShoppingSummary 收尾时提取新偏好  
  - 读取时机：新会话开始时 read_relevant() 注入 system prompt  
  - 进化能力：无（写了就存着，过期靠软衰减）  

```  

### 1.2 本章要升级到什么  
```text  
升级后的 Store：  
  - 存什么：偏好（已有）+ 成功策略（新增）+ 失败教训（新增）  
  - 写入时机：偏好（同前）+ 高分轨迹自动提炼策略 + 低分轨迹记录教训  
  - 读取时机：新会话时检索相似 query 的策略 → 注入 system prompt 作为参考  
  - 进化能力：策略有 confidence 分 / 软衰减 / 验证门禁 / 被引用时加分  

```

## 2、什么是"成功策略"  

### 2.1 定义  
> **成功策略 = 某类 query + 某种工具调用序列 → 高 Rubric 分 → 提炼为可复用的经验**     

不是存完整轨迹（太长），而是存"轨迹的精华总结"——让 Agent 下次遇到类似 query 时不用从零探索。  

### 2.2 一条策略长什么样  
```python  
# app/memory/strategy.py  
from pydantic import BaseModel, Field  
from datetime import datetime  


class StrategyEntry(BaseModel):  
    """一条成功策略。"""  
    strategy_id: str  
    query_pattern: str              # 适用的 query 模式（如"跨平台旅行三件套类"）  
    summary: str                    # 50 字以内的策略摘要  
    tool_hints: list[str]           # 推荐的工具调用顺序  
    key_decisions: list[str]        # 关键决策点（如"先 CategoryInsight 再 fork"）  
    rubric_score: float             # 产出这条策略的轨迹的 Rubric 分  
    confidence: float = 1.0         # 置信度（随时间衰减 / 被引用时回升）  
    times_referenced: int = 0       # 被引用次数  
    created_at: datetime = Field(default_factory=datetime.now)  
    source_trace_id: str | None = None  

```  

### 2.3 真实示例  
```yaml  
strategy_id: "strat-001"  
query_pattern: "跨平台比价类（涉及预算约束 + 材质排除）"  
summary: "先 CategoryInsight 确认品类组件，再 fork 4 路并行搜索，合流后比价 + 算运费，最后按预算硬约束 + 材质黑名单精挑"  
tool_hints:  
  - "category_insight(depth=quick)"  
  - "dispatch_tool × 4"  
  - "price_compare"  
  - "shipping_calc"  
  - "item_picker"  
  - "shopping_summary"  
key_decisions:  
  - "品类不确定时先调 CategoryInsight 不要直接搜"  
  - "4 个平台全部可用时走 fork 并行，某平台熔断时只搜可用平台"  
  - "材质排除在 item_picker 而非 item_search 处理"  
rubric_score: 0.88  
confidence: 0.95  
times_referenced: 12  

```

## 3、策略的全链路：产出 → 存储 → 检索 → 注入  

### 3.1 Step 1：从高分轨迹中提炼策略  
```python  
# app/evolution/strategy_extractor.py  
from app.agent.llm import get_judge_llm  
from app.memory.strategy import StrategyEntry  


EXTRACT_PROMPT = """你是 Globex 的策略提炼器。  

给定一条 Rubric 分 >= 0.80 的成功轨迹摘要：  
  query: {query}  
  工具调用序列: {tool_sequence}  
  Rubric 分: {score}  

请提炼出一条可复用的成功策略，格式：  
  query_pattern: 用一句话描述这条策略适用于什么类型的 query  
  summary: 50 字以内的策略核心思路  
  tool_hints: 推荐的工具调用顺序（列表）  
  key_decisions: 2-3 条关键决策点  

只输出 JSON，不要解释。"""  


async def extract_strategy(  
    query: str,  
    tool_sequence: list[str],  
    score: float,  
    trace_id: str,  
) -> StrategyEntry | None:  
    """从高分轨迹中提炼成功策略。"""  
    if score < 0.80:  
        return None  

    llm = get_judge_llm()  
    resp = await llm.ainvoke([  
        ("user", EXTRACT_PROMPT.format(  
            query=query,  
            tool_sequence=", ".join(tool_sequence),  
            score=score,  
        )),  
    ])  

    import json  
    try:  
        data = json.loads(resp.content)  
        return StrategyEntry(  
            strategy_id=f"strat-{trace_id[:8]}",  
            query_pattern=data["query_pattern"],  
            summary=data["summary"],  
            tool_hints=data["tool_hints"],  
            key_decisions=data["key_decisions"],  
            rubric_score=score,  
            source_trace_id=trace_id,  
        )  
    except (json.JSONDecodeError, KeyError):  
        return None  

```  

### 3.2 Step 2：存储策略  

策略存到和偏好一样的 Store 里（Redis / Postgres），但有独立的 namespace：  
```python  
# app/memory/store.py（扩展）  
STRATEGY_NAMESPACE = "strategy"  


async def write_strategy(strategy: StrategyEntry):  
    """写入成功策略。"""  
    # 向量化 query_pattern + summary 用于后续语义检索  
    embedding = await tower_client.encode_query(  
        f"{strategy.query_pattern} {strategy.summary}"  
    )  
    await _store_backend.put(  
        namespace=STRATEGY_NAMESPACE,  
        key=strategy.strategy_id,  
        value=strategy.model_dump(),  
        embedding=embedding,  
    )  

```  

### 3.3 Step 3：检索相似策略  

新会话开始时，用用户 query 检索最相关的 1-3 条策略：  
```python  
# app/memory/store.py（扩展）  

async def read_relevant_strategies(query: str, top_k: int = 3) -> list[StrategyEntry]:  
    """检索和当前 query 最相关的成功策略。"""  
    embedding = await tower_client.encode_query(query)  
    results = await _store_backend.search(  
        namespace=STRATEGY_NAMESPACE,  
        embedding=embedding,  
        top_k=top_k,  
        min_confidence=0.3,  # 置信度太低的不返回  
    )  
    return [StrategyEntry(**r["value"]) for r in results]  

```  

### 3.4 Step 4：注入 system prompt  
```python  
# app/memory/injector.py（扩展）  

def inject_strategies(prompt: str, strategies: list[StrategyEntry]) -> str:  
    """把成功策略注入 system prompt 末尾。"""  
    if not strategies:  
        return prompt  

    strategy_text = "\n".join(  
        f"- [{s.query_pattern}] {s.summary}（推荐顺序：{' → '.join(s.tool_hints[:4])}）"  
        for s in strategies[:3]  
    )  

    injection = f"""  
# 成功策略参考（来自历史高分轨迹，可选择性参考）  
{strategy_text}  

注意：以上策略仅供参考，请根据当前 query 的具体情况灵活调整。  
"""  
    return prompt + injection  

```  

**关键设计**：注入是"参考"不是"强制"——加了"可选择性参考"和"灵活调整"的提示，防止模型机械照搬。

## 4、策略的验证门禁与生命周期  

### 4.1 写入前验证  

不是所有高分轨迹都值得提炼策略。门禁：  

| 门禁  | 条件  | 原因  |  
|-------|-------|-------|  
| Rubric 分  | >= 0.80  | 低于这个分不算"成功"  |  
| 轨迹轮次  | >= 4 轮 Act  | 太短的轨迹没有"策略"可提炼  |  
| 工具多样性  | 至少用了 3 个不同工具  | 只调 1-2 个工具的轨迹没策略价值  |  
| 去重  | 和已有策略语义相似度 < 0.85  | 避免存大量重复策略  |  

### 4.2 置信度衰减 + 引用回升  
```python  
# app/memory/strategy_lifecycle.py  
import math  
from datetime import datetime, timedelta  


def compute_confidence(strategy: StrategyEntry) -> float:  
    """计算策略的当前置信度。"""  
    # 时间衰减：半衰期 60 天  
    days_old = (datetime.now() - strategy.created_at).days  
    time_decay = math.exp(-0.693 * days_old / 60)  # ln(2) ≈ 0.693  

    # 引用回升：每被引用一次加 0.05，上限 1.0  
    reference_boost = min(strategy.times_referenced * 0.05, 0.5)  

    # 综合置信度  
    confidence = min(1.0, strategy.rubric_score * time_decay + reference_boost)  
    return round(confidence, 3)  

```  

**衰减逻辑**：  
- 60 天没被引用 → 置信度降到原来的 50%  
- 180 天没被引用 → 置信度降到 12%（几乎不会被检索出来）  
- 但如果期间被引用了 5 次 → 置信度回到 0.75+  

### 4.3 策略被引用时的反馈  

当一条策略被注入到某次请求的 system prompt 后：  
- 如果该请求的 Rubric 分 >= 0.75 → `times_referenced += 1`（策略有效）  
- 如果该请求的 Rubric 分 < 0.50 → `confidence -= 0.1`（策略可能误导了 Agent）  
```python  
# app/evolution/strategy_feedback.py  

async def feedback_on_strategy(strategy_id: str, rubric_score: float):  
    """策略被引用后的反馈机制。"""  
    strategy = await store.get_strategy(strategy_id)  
    if strategy is None:  
        return  

    if rubric_score >= 0.75:  
        strategy.times_referenced += 1  
    elif rubric_score < 0.50:  
        strategy.confidence = max(0.0, strategy.confidence - 0.1)  

    await store.write_strategy(strategy)  

```

## 5、Fork 策略的动态调整  

### 5.1 问题：静态 fork 候选列表  

第 14 章里 fork 4 路是写死的：amazon / shopee / aliexpress / ebay。但现实中：  
- 某平台 API 最近一周连续超时 → 不该再 fork 给它  
- 某平台在某品类下商品很少 → fork 了也搜不到有用结果  
- 新平台接入了 → 应该自动进入 fork 候选  

### 5.2 基于历史成功率动态调整  
```python  
# app/evolution/fork_optimizer.py  
from collections import defaultdict  


class PlatformSuccessTracker:  
    """跟踪各平台的历史成功率。"""  

    def __init__(self):  
        self._stats: dict[str, dict] = defaultdict(  
            lambda: {"success": 0, "total": 0}  
        )  

    def record(self, platform: str, success: bool):  
        self._stats[platform]["total"] += 1  
        if success:  
            self._stats[platform]["success"] += 1  

    def get_success_rate(self, platform: str) -> float:  
        stats = self._stats[platform]  
        if stats["total"] == 0:  
            return 0.5  # 无数据时默认 50%  
        return stats["success"] / stats["total"]  

    def get_ranked_platforms(self) -> list[tuple[str, float]]:  
        """按成功率降序排列所有平台。"""  
        ranked = [  
            (platform, self.get_success_rate(platform))  
            for platform in self._stats  
        ]  
        ranked.sort(key=lambda x: x[1], reverse=True)  
        return ranked  

    def should_fork_to(self, platform: str, threshold: float = 0.3) -> bool:  
        """成功率低于阈值的平台不建议 fork。"""  
        return self.get_success_rate(platform) >= threshold  


platform_tracker = PlatformSuccessTracker()  

```  

### 5.3 动态 fork 候选列表  
```python  
# app/agent/dynamic_fork.py  
from app.evolution.fork_optimizer import platform_tracker  

DEFAULT_PLATFORMS = ["amazon", "shopee", "aliexpress", "ebay"]  
MIN_SUCCESS_RATE = 0.3  # 低于 30% 的平台从候选里移除  


def get_fork_candidates() -> list[str]:  
    """获取当前适合 fork 的平台列表。"""  

    candidates = [ ]  

    for platform in DEFAULT_PLATFORMS:  
        if platform_tracker.should_fork_to(platform, MIN_SUCCESS_RATE):  
            candidates.append(platform)  

    # 至少保留 2 个平台（即使都差也不能完全没有）  
    if len(candidates) < 2:  
        ranked = platform_tracker.get_ranked_platforms()  
        candidates = [p for p, _ in ranked[:2]]  

    return candidates  

```  

### 5.4 注入到主 loop 的 Think 阶段  

在 `pre_think` Hook 里动态注入当前可用平台信息：  
```python  
# app/harness/hooks/fork_hint.py  
from app.harness.middleware import harness_hook  
from app.agent.dynamic_fork import get_fork_candidates  


@harness_hook("pre_think", name="fork_platform_hint", priority=30)  
async def inject_fork_hint(context: dict) -> dict | None:  
    """注入当前推荐的 fork 平台列表。"""  
    candidates = get_fork_candidates()  

    if len(candidates) < 4:  
        # 有平台被移除了，需要告知主 loop  

        context.setdefault("inject_messages", []).append({  

            "role": "system",  
            "content": (  
                f"[平台状态更新] 当前推荐 fork 的平台：{', '.join(candidates)}。"  
                f"其他平台因近期成功率较低暂不建议检索。"  
            ),  
        })  

    return context  

```

## 6、失败教训的记录

### 6.1 不只存"成功"，也存"失败"

成功策略告诉 Agent "这样做好"。但还有另一面：告诉 Agent "这样做不好"。

```python
# app/memory/lesson.py
from pydantic import BaseModel


class LessonEntry(BaseModel):
    """一条失败教训。"""
    lesson_id: str
    query_pattern: str
    what_went_wrong: str       # 一句话说清楚错在哪
    avoid_hints: list[str]     # 应该避免什么
    rubric_comment: str        # Rubric judge 的扣分理由
    confidence: float = 1.0
```

### 6.2 教训的注入

和策略注入一起放在 system prompt 末尾：

```text
# 成功策略参考（来自历史高分轨迹）
- [跨平台比价类] 先 CategoryInsight 确认品类组件...

# 失败教训参考（来自历史低分轨迹）
- [旅行三件套] 不要跳过 CategoryInsight 直接搜——容易遗漏"三件套"的标准组件
- [送礼类 query] 不要只搜商品名——要考虑收礼人的属性（年龄/性别/爱好）
```

**注入后模型自己决定采纳哪条**——教训是"提醒"不是"禁令"。

## 本章小结

到这里，Globex 的记忆层从"被动存储"升级到了"主动进化"：

1. **成功策略**：从高分轨迹中自动提炼（query_pattern + summary + tool_hints + key_decisions），语义检索注入新会话。
2. **策略生命周期**：写入门禁（Rubric >= 0.80 + 去重）→ 置信度衰减（半衰期 60 天）→ 引用回升 → 负反馈降权。
3. **失败教训**：从低分轨迹中提取"应该避免什么"，和策略一起注入。
4. **Fork 动态调整**：基于平台历史成功率自动从 fork 候选里移除/恢复平台。
5. **策略是"参考"不是"强制"**：注入时明确说"可选择性参考"，防止模型机械照搬。
6. **和 Prompt 自进化的区别**：Prompt 是全体用户共享的规则变更；策略是个性化 + 场景化的经验积累——两者互补。

至此，Agent 自进化四章全部完成。Globex 从"上线后不变"变成了"越用越聪明"——通过四条进化路径（改记忆/改 Prompt/改工具/训模型）在不同时间尺度上持续变好，65% 的退化秒到分钟级修复，剩余 35% 周到月级通过训练推天花板。
