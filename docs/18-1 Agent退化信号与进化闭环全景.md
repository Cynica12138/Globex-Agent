# 18-1 Agent退化信号与进化闭环全景

## 本章课程目标

- 理解为什么 Agent 会“越用越差”——四类退化信号的识别和成因。
- 掌握 **3×3 进化矩阵框架**：What Evolves（三层）× When Persists（三范围），把“自进化”从模糊概念变成可工程化的分类体系。
- 理解 Globex 的进化闭环全景：**Monitor → Analyze → Plan → Evolve（MAPE）**，以及它和评测（第 8 章）/ 观测（16-3）/ Harness（17 章）的关系。
- 看清“修 Prompt vs 训模型 vs 改记忆 vs 改工具”四种进化路径的成本、收益和速度对比，知道什么时候该走哪条。

## 1、为什么 Agent 会“越用越差”

### 1.1 静态 Agent 的宿命

一个上线后再也不改的 Agent，即使 Day 1 表现优秀，也会随时间退化。

原因不是 Agent 自身代码劣化了，而是**它周围的一切都在变**：

```text
模型版本升级 → 旧 Prompt 的行为漂移
平台 API 更新 → 工具返回格式不兼容
用户需求演化 → 新品类 / 新场景没有知识覆盖
竞品体验提升 → 用户期望水位上涨
```

### 1.2 四类退化信号

| 退化类型 | 表现 | 典型来源 | 监控指标 |
|---|---|---|---|
| **Quality Drift** | Rubric 日均分持续下滑 | 闭源模型版本升级 / 数据分布偏移 | Rubric 7 日均分趋势 |
| **Tool Decay** | 某平台工具成功率骤降 | 平台 API 行为变更 / 反爬策略升级 | 工具成功率滑动窗口 |
| **Preference Stale** | 用户偏好变了，但 Agent 还按旧偏好推荐 | Store 里的偏好过期 / 季节性变化 | 偏好命中率下降 |
| **Context Rot** | Prompt 和实际工具集不匹配 | 新增 / 删除工具但 Prompt 未同步 | 工具调用 404 率 |

### 1.3 退化的“温水煮青蛙”效应

退化通常不是断崖式的——断崖式问题反而容易被发现。

真正危险的是这种情况：

```text
Day 1   Rubric = 79
Day 7   Rubric = 77
Day 14  Rubric = 74
Day 21  Rubric = 71
Day 30  Rubric = 68
```

每天可能只下降约 `0.5%`，单独看一天并不明显，但连续一个月后，整体质量已经从 79 分降到了 68 分。

如果没人持续观察趋势曲线，就会积累严重的用户体验损失。

因此：

> **自进化的核心动机：不能等人发现了再修，而要让系统自己发现，并尽可能自己修复。**

## 2、3×3 进化矩阵：行业标准框架

### 2.1 What Evolves：进化什么

一个 Agent 系统里有三个“可变层”，从外到内：

```text
┌───────────────────────────────────────────────┐
│ Layer 1: External Files                       │ ← 便宜、即时、可逆
│ （记忆 / 知识 / 技能库 / 成功策略）             │
├───────────────────────────────────────────────┤
│ Layer 2: Agent Harness                        │ ← 中等成本
│ （Prompt / 工具定义 / 工作流逻辑 / 路由规则）   │
├───────────────────────────────────────────────┤
│ Layer 3: Model Weights                        │ ← 贵、慢、持久
│ （参数化知识 / 核心决策能力）                   │
└───────────────────────────────────────────────┘
```

核心规律：

```text
越往外
→ 越便宜
→ 越快
→ 越容易回滚
→ 越适合频繁迭代

越往内
→ 越昂贵
→ 越慢
→ 影响越持久
→ 越适合解决能力上限问题
```

因此生产系统中的基本原则是：

> **优先走外层进化，只有外层解决不了的问题，才继续往模型权重层走。**

---

### 2.2 When Persists：进化结果持续多久

| 持久范围 | 含义 | 例子 |
|---|---|---|
| **Single Session** | 只在当次会话内有效 | 临时 Scratchpad / 工具返回缓存 |
| **Across Sessions** | 同一用户或任务跨会话持续存在 | Store 偏好 / 成功策略 / Checkpoint |
| **Across Users** | 对全体用户生效 | 模型 SFT / RL / 默认 Prompt 升级 |

---

### 2.3 完整 3×3 进化矩阵

把 What Evolves 和 When Persists 两个维度组合起来：

|  | External Files | Agent Harness | Model Weights |
|---|---|---|---|
| **Single Session** | 临时记忆（Scratchpad） | 动态工具编排（17-4 阶段状态机） | 极少使用（Test-Time Training） |
| **Across Sessions** | 偏好 Store + Skill Library | Prompt 版本化 + 工具增删 | 参数化个性化（Frontier） |
| **Across Users** | 共享知识库 + 策略 Commons | 默认 Prompt 全量升级 | SFT / RL 训练 |

这样一来，“Agent 自进化”就不再是一个模糊概念，而是被拆成了 **9 个明确的工程格子**。

---

### 2.4 Globex 的进化路径映射

Globex 当前已经具备一部分能力，18-2 / 18-3 / 18-4 会继续补齐剩余部分。

| 矩阵格子 | Globex 已有 | 还缺什么 |
|---|---|---|
| Files × Session | 第 6 章 Store 读写 | 已充分 |
| Files × Across | Store 跨会话持久化 | **成功策略 / Skill Library（18-4）** |
| Files × Users | CategoryInsight RAG 知识库 | **共享策略 Commons（18-4）** |

| Harness × Across | 无 | **Prompt 版本化 + A/B（18-3）** |
| Harness × Users | 无 | **默认 Prompt 自动升级（18-3）** |
| Weights × Session | 不做 | 不做，成本不合理 |
| Weights × Across | 不做 | 不做，属于 Frontier 研究 |

## 3、Globex 进化闭环：Monitor → Analyze → Plan → Evolve

### 3.1 MAPE 控制论框架

Globex 的自进化体系可以抽象为一个 MAPE 闭环：

```text
┌─────────────────────────────────────────────────────────────┐
│                    Globex 进化闭环                           │
│                                                             │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌────────┐ │
│  │ Monitor  │───→│ Analyze  │───→│   Plan   │───→│ Evolve │ │
│  │ 监测退化  │    │ 定位根因  │    │ 选进化路径│    │ 执行进化│ │
│  └──────────┘    └──────────┘    └──────────┘    └────────┘ │
│       ↑                                              │      │
│       └────────────── 部署 + 验证 ───────────────────┘      │
└─────────────────────────────────────────────────────────────┘
```

对应四个阶段：

```text
Monitor
发现“哪里变差了”
        ↓
Analyze
判断“为什么变差”
        ↓
Plan
决定“应该改哪里”
        ↓
Evolve
真正执行修改
        ↓
Deploy + Evaluate
部署并验证
        ↓
重新进入 Monitor
```

---

### 3.2 四步拆解

| 步骤 | 做什么 | 依赖什么基建 |
|---|---|---|
| **Monitor** | 发现 Rubric 分下降 / 工具失败率上升 / 偏好命中率下降 | LangFuse（16-3） |
| **Analyze** | 按 P0 / P1 / P2 定位根因：格式问题、决策问题还是知识缺失 | Rubric 评测（第 8 章） |
| **Plan** | 根据根因选择进化路径：改记忆、改 Prompt、改工具还是训模型 | 本章 §4 决策表 |
| **Evolve** | 执行进化并验证效果 | 18-2 / 18-3 / 18-4 |

---

### 3.3 和已有章节的拼图关系

Globex 前面的章节其实已经在为自进化做准备：

```text
第 8 章 Rubric
    ↓
Monitor 的“温度计”
负责发现整体质量是否下降

16-3 LangFuse
    ↓
Monitor / Analyze 的“X 光机”
负责定位到底是哪一步出了问题

17-1 ~ 17-4 Harness
    ↓
防御层
避免一次错误直接把 Agent 带崩

18-1 ~ 18-4 自进化
    ↓
修复层
让系统在发生退化后继续变好
```

可以概括成一句话：

> **Harness 防摔，自进化会跑。**

两者结合：

```text
Harness
→ 防止 Agent 一次失败造成严重事故

Self-Evolution
→ 让 Agent 从失败中持续学习
```

最终得到：

```text
可靠性 + 持续进化能力
= 一个长期可运营的 Agent 系统
```

## 4、四条进化路径的成本-收益-速度对比

### 4.1 决策表

当 Monitor 检测到退化之后，并不是所有问题都应该直接去训模型。

| 进化路径 | 修什么 | 生效速度 | 成本 | 解决什么级别的问题 |
|---|---|---|---|---|
| **改记忆** | Store + Skill | 秒级 | 几乎为零 | 偏好过期 / 成功策略缺失 |
| **改 Prompt** | System Prompt | 分钟级 | 极低 | 规则缺失 / 措辞不当 / 新场景适配 |
| **改工具 / Harness** | 工具定义 / Hook | 小时级 | 低 | 工具行为变更 / 新工具接入 |
| **训模型** | SFT / RL | 天级 | 高 | 决策质量天花板 / 范式理解不足 |

整体成本梯度：

```text
改记忆
  ↓
改 Prompt
  ↓
改工具 / Harness
  ↓
训模型

快 ─────────────────────────→ 慢
便宜 ───────────────────────→ 贵
容易回滚 ───────────────────→ 难回滚
```

---

### 4.2 决策流程

面对一个退化问题，可以按照下面的顺序判断：

```text
退化信号出现
  ↓
Step 1：是偏好 / 知识问题吗？
  │
  ├─ 是
  │   ↓
  │  走记忆层进化（18-4）
  │   ↓
  │  秒级生效
  │
  └─ 否
      ↓
Step 2：是规则 / Prompt 措辞问题吗？
  │
  ├─ 是
  │   ↓
  │  走 Prompt 自进化（18-3）
  │   ↓
  │  分钟级 A/B 验证
  │
  └─ 否
      ↓
Step 3：是工具 / 环境发生变化了吗？
  │
  ├─ 是
  │   ↓
  │  修工具 + 修改 Harness Hook
  │   ↓
  │  小时级
  │
  └─ 否
      ↓
Step 4：是模型本身的决策质量问题吗？
  │
  └─ 是
      ↓
     SFT / RL 训练飞轮（18-2）
      ↓
     天级
```

核心原则：

> **永远从成本最低的路径开始试。能用改记忆解决的问题，绝不直接训模型。**

---

### 4.3 80/20 法则

Globex 线上退化可以粗略拆成下面几类：

| 根因类型 | 占比 | 对应进化路径 |
|---|---:|---|
| 偏好过期 / 知识缺失 | ~35% | 改记忆（18-4） |
| Prompt 规则缺失 | ~30% | 改 Prompt（18-3） |
| 工具行为变更 | ~20% | 改工具 / Harness |
| 模型决策不够好 | ~15% | 训模型（18-2） |

也就是说：

```text
35% 记忆问题
+
30% Prompt 问题
=
65%
```

**约 65% 的退化可以在不训练模型的情况下解决。**

这也是外层进化路径存在的核心价值：

```text
不是所有失败
        ↓
都应该变成训练样本
        ↓
很多失败其实只是配置、知识或 Prompt 问题
```

## 5、学术分类框架补充

### 5.1 三大维度

对照 Agent 自进化相关学术分类，Globex 的能力大致可以映射为：

| 学术维度 | Globex 对应 |
|---|---|
| **Model-Centric Evolution** | 08-1 / 08-2 SFT + RL 训练（Training-Based Evolution） |
| **Environment-Centric Evolution** | 18-2 数据飞轮（Dynamic Experience）+ 18-4 策略沉淀（Skill Augmented） |
| **Model-Environment Co-Evolution** | 完整飞轮：RL 训练 → 线上运行 → 新数据 → 新一轮 RL |

其中：

```text
Model-Centric
→ 改模型本身

Environment-Centric
→ 不动模型，通过记忆、工具、Skill、知识等外部环境增强模型

Co-Evolution
→ 模型和环境一起进化
```

Globex 最终追求的是第三种：

```text
线上 Agent 产生经验
        ↓
经验进入 Skill / Memory
        ↓
Bad Case 进入训练集
        ↓
SFT / RL 更新模型
        ↓
新模型重新上线
        ↓
产生新的经验
        ↓
循环
```

---

### 5.2 Globex 的进化“护城河”

相比只会人工改 Prompt 或周期性重新训模型的 Agent，Globex 希望形成一个多层进化体系：

| 常见做法 | Globex 做法 | 优势 |
|---|---|---|
| 纯 Prompt 人工调参 | Prompt 版本化 + 自动 A/B 测试 | 可回滚、可量化、可自动化 |
| 单一模型训练 | 外层先修 → 内层兜底 | 大量问题不需要等待训练 |
| 无 Skill Library | 成功策略自动蒸馏 + 向量检索注入 | 历史成功经验可以复用 |
| 无 Bad Case 自动流转 | P0 / P1 / P2 自动分流到对应路径 | 降低人工定位成本 |

Globex 的核心并不是“训练次数更多”，而是：

> **不同类型的问题进入不同成本等级的修复通道。**

也就是：

```text
简单问题
→ 快速外层修复

复杂问题
→ Harness 修复

能力上限问题
→ 模型训练
```

这样才能真正形成可长期运行的 Agent 进化体系。

## 本章小结

到这里，你应该对 Agent 自进化有了一套系统性的理解。

### 1. 四类退化信号

```text
Quality Drift
Tool Decay
Preference Stale
Context Rot
```

Agent 很多时候不是“自己变笨了”，而是：

> **周围环境已经变化，但它没有同步变化。**

### 2. 3×3 进化矩阵

两个维度：

```text
What Evolves
├── External Files
├── Agent Harness
└── Model Weights
```

以及：

```text
When Persists
├── Single Session
├── Across Sessions
└── Across Users
```

组合以后形成 9 个可工程化的 Agent 自进化格子。

### 3. MAPE 进化闭环

```text
Monitor
   ↓
Analyze
   ↓
Plan
   ↓
Evolve
   ↓
Deploy + Evaluate
   ↓
Monitor
```

并且和已有系统形成完整拼图：

```text
Rubric
→ 发现退化

LangFuse
→ 定位退化

Harness
→ 防止退化造成严重事故

Self-Evolution
→ 修复退化并持续提升
```

### 4. 四条进化路径

按成本从低到高：

```text
改记忆
  ↓
秒级

改 Prompt
  ↓
分钟级

改工具 / Harness
  ↓
小时级

SFT / RL 训模型
  ↓
天级
```

基本原则：

> **永远优先从最便宜、最快、最容易回滚的外层开始。**

### 5. 65% 的退化不需要训练模型

```text
偏好 / 知识问题   ~35%
Prompt 问题      ~30%
----------------------
合计             ~65%
```

因此 Agent 自进化并不等于“不断重新训练模型”。

真正成熟的自进化系统应该是：

> **记忆、Prompt、Harness 和模型权重四层共同进化。**
